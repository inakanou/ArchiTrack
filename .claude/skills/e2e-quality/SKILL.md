# E2Eテスト品質基準

このスキルはE2Eテストに関する作業時の品質基準を定義する。
以下の基準はすべてのE2Eテスト作業において絶対的に遵守すること。

## 1. テスト合否の判定基準

テストの合格・不合格は**要件を満たしているか否か**のみを基準とする。

- テストが失敗した場合、まず対応する要件（REQ-xx.x）を確認し、実装が要件を満たしているかを検証する
- 要件を満たしている実装に対してテストが失敗する場合は、テストコード側の問題として修正する
- 要件を満たしていない実装に対してテストが失敗する場合は、実装側の問題として修正する
- テストの成功は「要件が正しく実装されていることの証明」でなければならない

## 2. テストスキップの禁止

テストを無断でスキップ・無効化することは一切禁止する。

### 禁止される操作

- `test.skip()` によるテストのスキップ
- `test.fixme()` によるテストの保留
- `test.describe.skip()` によるテストグループのスキップ
- 条件分岐による実質的なスキップ（常にtrueとなる条件でのスキップ等）
- `expect` アサーションのコメントアウトや削除
- テストケース自体のコメントアウトや削除

### テスト失敗時の正しい対応

1. 失敗の根本原因を調査する
2. 要件に照らして実装とテストのどちらに問題があるかを判断する
3. 問題のある側（実装またはテスト）を修正する
4. 修正後、テストが正しく通過することを確認する

## 3. 要件カバレッジ

テストコードを追加・修正する際は、要件との対応関係を明確にすること。

- テストファイルの先頭に `Requirements coverage` コメントで対応要件を明記する
- 各テストケースが検証する要件を特定可能な形で記述する
- 要件に対応しないテストを無意味に追加しない
- 未カバーの要件がある場合は、その旨を報告する
