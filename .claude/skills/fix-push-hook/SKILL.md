# git pushフック失敗対応ガイドライン

## 1. ログ調査手順（コンテキスト節約）

ログファイル `.logs/pre-push-latest.log` を以下の手順で調査する。ログ全体を一括で読み込んではならない。

1. **末尾から読む**: ログの末尾（最後の50〜100行程度）を読み、失敗要因のサマリーやエラーメッセージを特定する
2. **失敗箇所を遡る**: 特定した失敗要因をもとに、関連するキーワードでログ内を検索し、具体的な失敗箇所を絞り込む
3. **必要最小限の読み取り**: 失敗箇所の前後のみを読み取り、原因を確定する

### 禁止事項

- ログファイル全体を一括で読み込むこと
- 失敗要因が不明なままログを先頭から順に読むこと

## 2. 修正対応

失敗原因を特定したら、該当箇所を修正する。

## 3. 作業完了の定義

修正後、git pushフックの再実行は行わない。修正内容と対応結果をユーザーに報告して作業完了とする。
