# 除外の代替検証と受入基準の被覆範囲の裁定一覧（タスク 115.189）

`e2e/requirement-exclusions.json` の各除外が掲げる**代替検証**（「E2Eでは確かめないが、
代わりにこの方法で確かめる」という約束）が、その除外が指す受入基準の**原文**の求める内容を
どこまで覆っているかを、母集団の全件について裁定した記録である。

**なぜ問題になるか。** 除外は受入基準を**丸ごと**被覆率の分母から外す。約束が原文の一部しか
述べていなければ、述べられていない部分は「E2Eでも確かめず、代わりの方法でも確かめない」まま、
どの指標にも現れなくなる。**部分被覆を「除外」と呼ぶと、覆われていない部分が消える。**

## 1. 母集団の確定（走査は再現できる）

走査は `scripts/scan-exclusion-alternative-coverage.ts` にある。合否は出さない。

```
npx tsx scripts/scan-exclusion-alternative-coverage.ts            # 全件を一致度の昇順で
npx tsx scripts/scan-exclusion-alternative-coverage.ts --missing  # 列挙の欠落がある件だけ
npx tsx scripts/scan-exclusion-alternative-coverage.ts --tsv      # 機械可読
npx tsx scripts/scan-exclusion-alternative-coverage.ts --comma-rule  # 読点の規則の試作（§8）
```

**下表の実測は着手時（HEAD 86882dd）の母集団に対するもので、是正後の除外リストに対して
そのまま走らせても再現しない**（是正で 206→205 件へ動いているため）。過去の版に対して
走らせる `--exclusions` を走査に置いたので、下表は次の二行で再現できる。

```
git show 86882dd:e2e/requirement-exclusions.json > /tmp/head-exclusions.json
npx tsx scripts/scan-exclusion-alternative-coverage.ts --exclusions /tmp/head-exclusions.json
# → 除外 206件 / 中黒で二つ以上を列挙する原文 18件 / 述べていない要素がある 13件 /
#    一致度の中央値 0.2075
```

**起票文の二件は着手時に測り直した。**

| 起票文が挙げた件 | 着手時（HEAD 86882dd）の実測 |
| --- | --- |
| `site-survey/REQ-8.5` の説明が「フォントサイズ」だけで色・背景色を含まない | **実在した**（除外 `exclusions[51]`。原文の列挙 `フォントサイズ・色・背景色` のうち「色」「背景色」を代替検証が述べていない） |
| `quantity-table-generation/REQ-7.3` の説明が大項目・中項目を含まない | **既に存在しない**。当該の除外はタスク 115.186（`38e80c9`）で取り下げ済みで、HEAD の 206 件に無い |

母集団の実測（HEAD の 206 件）:

| 指標 | 実測 |
| --- | --- |
| 除外の総数（母集団） | **206** |
| 原文が中黒（`・`）で二つ以上を列挙する除外 | 18 |
| そのうち代替検証が述べていない要素を残しているもの | **13** |
| 原文と代替検証の文字bigram一致度の中央値 | 0.2075 |

**中央値は真の中央値（偶数件のときは中央の二つの平均）で測っている。** 走査の初版は
`sorted[Math.floor(n / 2)]` で**上側**の中央値を返しており、206 件（偶数）では 0.2099 を出して
本表の 0.2075 と食い違っていた。**記録の数値がその記録の名乗るコマンドで再現できない状態を
残さないため、走査の側を真の中央値へ直した**（昇順 103 位 0.2051 と 104 位 0.2099 の平均が
0.2075）。奇数件では出力は変わらない（是正後の 205 件は前後とも 0.3143）。

**一致度は順序づけの道具であって判定の道具ではない。** 起票文が名指しした
`site-survey/REQ-8.5` は一致度 0.2778 で **206 件中 136 位**（昇順）だった。
**下位帯だけを見る裁定では取りこぼす。** ゆえに順序づけに頼らず、**206 件を全件裁定した。**

## 2. 裁定の基準（一件ごとの数え上げで決める）

各除外について、次の手順を一件ずつ踏む。

1. **原文の結論部（`shall` 以降）が求める観測を数え上げる。** 中黒の列挙、読点の列挙、
   動詞句の連言（「〜を表示し、〜を促す」）、「〜して、〜する」で後段が独立に観測できる結果を
   述べている形は、いずれも別々の観測として数える。
2. `alternativeVerification` の全欄（`method` / `tool` / `description` / `threshold`）が、
   数え上げた観測を**一つずつ名指ししているか**を見る。**照合の相手に `title` と `reason` は
   含めない。** この二つは「何を除外したか」の説明であって「代わりに何を確かめるか」の
   約束ではない。実データの `site-survey/REQ-8.5` は、題が「テキストのフォントサイズ・色・
   背景色のカスタマイズ」と原文を写しているのに、約束の側は「フォントサイズを変更できることを
   確認」だけだった。
3. 名指しの数で区分する。

| 区分 | 定義（数え上げの結果として決まる） | 扱い |
| --- | --- | --- |
| **P** | 観測を**一つ以上名指ししつつ、他を名指ししていない** | **本タスクで是正した**（§3） |
| **Z** | 観測を**一つも名指しせず**、手段の総称（「PDF生成ロジックを検証」など）だけを述べる | 是正しない。§4 に理由と全件 |
| **N** | 代替検証を**掲げていないと明示している**（`method: none`） | 是正しない。§5 に全件 |
| **F** | 数え上げた観測を**すべて名指ししている** | §6 に**全件表**（原文の観測・代替検証が名指しするもの・判定） |

> **F を「P でも Z でもないもの」と定義しない。** 初版はそう定義しており、130 件が残差のまま
> 一件ごとの記録を持たなかった。独立レビューが乱数種を変えた二回の抜き取り（計34件）で
> 標的の形の部分被覆を5件検出したため、**§6 に全件表を置き、観測の数え上げを明示した結果として
> F になる形へ改めた。** レビューが挙げた5件はいずれも §3.4 で P へ再分類してある。

機械集計（`scripts` 配下の裁定表を集計したもの。散文の数え上げではない）:

```
HEAD 母集団 206 = P(是正) 56 + Z(総称) 43 + N(代替検証なしと明示) 3 + F(覆っている) 104
  P の内訳: 説明を広げた 55 / 除外を取り下げた 1
是正後の除外件数 205（P のうち 55 件は除外のまま説明を実態へ広げた）
```

## 3. 本タスクで是正した除外（P: 56 件）

判断は三択から一件ずつ選んだ。**(a) 説明を実態へ広げる / (b) 代替検証を拡張する /
(c) 除外を取り下げる。** (b) は代替検証の実体が `frontend/src`・`backend/src` にあり
本タスクの _Boundary_ 外であるため、選べたのは (a) と (c) である。

> **(a) が達成したことと、していないことを分けて述べる。**
> (a) は「掲げた約束が受入基準の全体を覆う」ことを達成する。**「受入基準が検証される」ことは
> 達成しない。** 約束の実在（掲げた検証がリポジトリに在るか）は被覆率の検査が別に測っており、
> `scripts/check-requirement-coverage.ts` の `auditExclusions` が `in-repo-unverified` として
> 数え、`npm run check:req-coverage:strict` が赤で報告する。是正した 56 件のうち
> **是正後も緑（`in-repo-verified`）なのは4件だけ**で、残りは今も赤か `external` である。
> 是正はその赤を消していない。

**後記（タスク 115.329）**: 本節の表は 115.189 の当時の是正の記録として書き換えない。
表の行が名乗る除外がその後に取り下げられた件と、代替検証の説明がその後に改められた件は §10 にある。

### 3.3 唯一の (c): `site-survey/REQ-8.5` の除外を取り下げた

原文は「テキストのフォントサイズ・色・背景色をカスタマイズ可能にする」。掲げた代替検証は
`Vitest / React Testing Library` の統合テストで「フォントサイズを変更できることを確認」だけだった。
実測した事実は二つある。

- **色**: 掲げた代替検証にあたる `frontend/src/__tests__/components/site-surveys/StylePanel.test.tsx` は

  つまり **E2E が現に観測している内容であり、「E2E範囲外」という除外の前提が崩れている。**

## 8. 置いた検査と、その限界（両方向）

`scripts/check-requirement-exclusions.ts` に検査 `alternative-coverage` を新設した。
判定は次の一つだけである。

> **原文（`criterionText`）が中黒（`・`）で列挙する要素を、`alternativeVerification` の
> いずれかの欄が名指ししていること。**

散文どうしの照合は自然言語の判断であり機械化できない（115.167 が同じ結論に達している）。
そこで判定の対象を、**書式で切り出せる列挙**だけに限った。起票文が挙げた二件は、いずれも
この形である（8.5 の「フォントサイズ・色・背景色」、7.3 の「小項目・任意分類・工種…」に
対する大項目・中項目の欠落）。

**塞ぐもの:**

- 原文が中黒で並べた要素を、代替検証が一つでも落とす形。**要素が題（`title`）にしか
  書かれていない場合も落とす**（8.5 がまさにその形だった。自己検査の陽性対照で固定）。
- 要素を閾値（`threshold`）の欄で述べている除外は通す（実在するため。陰性対照で固定）。

**塞がないもの:**

- **中黒の列挙を持たない受入基準は判定しない。** 「エラーメッセージを表示し、ユーザーに
  再試行を促す」のような動詞句の連言は、項目の切り出しが自然言語の判断になるため決められない。
  §3.2 の 20 件と §3.4 の 23 件は人手の全件裁定で見つけたものであり、**同じ形の再発は機構では
  止まらない。** 読点（`、`）で並ぶ列挙まで項目の切り出しを広げる規則も試したが採らなかった。
  **その追試の手段を走査に残してある**（`--comma-rule`。`extractEnumeratedElements` の区切りを
  中黒から読点へ差し替えただけのもの）。HEAD（86882dd）の 206 件に対する実測は次のとおりで、
  **判定に使える形になっていない**。

  ```
  npx tsx scripts/scan-exclusion-alternative-coverage.ts --comma-rule \
    --exclusions /tmp/head-exclusions.json
  # → 除外 206件 中 46件
  #   うち切り出した項目に読点が残っている（項目の切り出しに失敗している）件: 11
  ```

  46 件の中身は、`execution-budget-management/REQ-8.4` の「た場合・最」、
  `construction-schedule/REQ-7.6` の「ユーザー」、`quantity-table-generation/REQ-15.3` の
  「ピッチ計算フィールド、」のように、**節の切れ目や活用語尾を項目と誤認した形**が大半である。
  読点は列挙の区切りだけでなく節の切れ目にも立つため、中黒と同じ手続きでは切り出せない。
  **なお、着手時に試した規則そのものは残していない。** 上の 46 件は残した `--comma-rule` の
  実測であって、着手時の試作の実測ではない（着手時の件数は再現手段が無いため本記録から外した）。
- **代替検証が原文の語を「書いている」ことしか見ない。** その観測が実在するか、実際に
  受入基準を確かめるかは見ない。実在の側は `auditExclusions` が `in-repo-unverified` として
  数える（HEAD の実測で 206 件中 163 件）。**この検査が緑でも、約束が果たされている保証は無い。**
  §3.4.1 の `quantity-table-generation/REQ-9.5` は、除外監査まで緑でありながら約束が
  果たされていなかった実例である。
- 要素の語が代替検証の文中で**別の意味**で使われていても見抜けない（語の一致しか見ない）。
- 除外の粒度そのもの（§9 の一つめ）。

項目の切り出しの規則（中黒の左右へ、助詞・活用語尾・記号に当たるまで伸ばす）は、
**実データ 206 件で測って決めた。** 境界の文字集合が無いと「選択された全ての項目に対して

削ってしまうため）。この規則は自己検査の機構対照で固定してある。
