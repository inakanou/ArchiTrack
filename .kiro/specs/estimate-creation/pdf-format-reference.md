# 見積書PDF出力 書式リファレンス

見積書PDF出力の目標書式。参照元は実案件の見積書PDF（`御見積書_JAあかし 農業倉庫改修工事_第2版.pdf`、8ページ、Producer: `Microsoft: Print To PDF`）。

参照PDFは一時領域に置かれた資料で永続しないため、実装に必要な寸法・配置をここに記録する。

## 座標系の読み方

参照PDFの各ページは `0.75 0 0 -0.75 0 595.32 cm` を適用しており、コンテンツは**96dpi ピクセル空間**（1122.56 × 793.76 px）で作られている。本書では以下2系統で表記する。

- **px**: 参照PDF内部の論理座標（左上原点、Y下向き）
- **mm**: 実寸（px × 0.264583）

フォントサイズも同様で、PDF内の `Tf` 値 × 0.75 が実際のポイント数になる。本書の pt はすべて実寸。

## 2. ページ構成

| ページ | 種別 | 内容 |
|---|---|---|
| 1 | **表紙** | 御見積書。宛先・見積金額・工事件名/場所・別途工事・自社情報 |
| 2 | **内訳書** | 第1階層項目の一覧＋値引行＋合計 |
| 3〜 | **明細書** | 第1階層ごとに改ページ。配下の子項目を列挙し、末尾に合計 |

### 明細書ページの生成ルール
- **子項目を持つ第1階層のみ**が明細書ページを持つ。
- 参照PDFでは内訳書に `Ａ`〜`Ｈ` ＋ `【値引】` の9行があるが、明細書は `Ａ`〜`Ｆ` の6ページのみ。`Ｇ.現場管理費` `Ｈ.一般管理費`（いずれも 式×1 の諸経費）と `【値引】` は子を持たないため明細書ページを作らない。
- 1ページに収まらない場合の継続処理は参照PDFに実例が無い（最大7明細行）。**要件定義で決める。**

## 7. 値の書式ルール

| 項目 | ルール |
|---|---|
| **数量** | 小数第1位まで表示し、**小数点位置を揃える**。整数値は小数部を空白で埋める（`1     ` / `612     ` / `343.1   ` / `53.7   `） |
| **単価・金額** | 3桁カンマ区切り、小数なし、右揃え。ゼロ・未設定は空欄 |
| **マイナス金額** | 先頭に `-`（`-48,585`） |
| **単位の繰り返し** | 直前行と同じ単位は `〃` に置換 |
| **表紙の金額** | **全角数字**＋全角カンマ（`￥１３,４２０,０００`）、末尾に `.- ` |
| **表紙の日付** | 全角数字（`２０２６ 年５ 月１ 日`） |
| **階層記号** | 全角英大文字 `Ａ` `Ｂ` `Ｃ` …（内訳書・明細書とも共通） |

## 9. 参照PDF側の不備（**再現しないこと**）

- Page 5 に、ページ幅（1063.4 px）を超える x=1164 / x=1340 の位置へ 41pt でテキストが配置されている（`機械的固定工法 土間部 8Φﾋﾞｽ使用`、`機械的固定工法 立上部 ﾊﾟﾗﾍﾟｯﾄ下部まで`）。**備考列に収まらず紙面外へはみ出したもの**で、書式の意図ではない。

### 要件定義で決める論点
1. **日本語フォントの選定と配布方法**: 埋め込みフォント（IPAex / Noto Sans JP 等）のライセンス、リポジトリ同梱かビルド時取得か、PDFサイズへの影響。
2. **PDF生成ライブラリの継続可否**: jsPDF で罫線グリッド＋日本語埋め込みを実現するか、サーバーサイド前提の別手段（HTMLテンプレート＋ヘッドレスブラウザ等）へ移行するか。
3. **明細が17行を超える場合**の継続ページの扱い（合計行の出し方、`Page.N` の連番、フッタの親項目名）。
4. **第3階層以降**の表現。参照PDFは2階層（第1階層＝内訳書の行、第2階層＝明細書の行）のみで実例が無い。
5. **表紙の固定文言・自社情報のデータ供給元**（`company-info` spec との連携）。
6. **別途工事①〜⑤・注記行・有効期限**の入力手段。現在の見積データモデルに対応するフィールドが無い。
7. **既存の行タイプ選択機能（REQ-32）との整合**。参照PDFは見積金額行のみの単一表。実行金額行・業者金額行を出力する場合の書式。
